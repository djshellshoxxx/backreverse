# BackReverse — Engineering Requirements and Notes

Cross-cutting rules, external prerequisites and quality gates for the roadmap in `09-feature-specifications.md` and `10-implementation-plan.md`. Items marked **[decision]** need a recorded decision (in this file, with the date) before the work that depends on them starts.

## 1. Compatibility rules (non-negotiable)

1. **Parameter IDs are permanent.** `src/plugin/Params.h` is append-only. IDs, order of existing entries, and the `Manufacturer`/`Plugin` codes (`Cdlb`, `Bkrv`) never change. Enforced by the guard test (plan §3, 0.2).
2. **State is versioned.** `formatVersion`, `productVersion`, `schemaVersion` are written by `stateTree()`. Any new key bumps `schemaVersion`, adds a migration in `applyStateTree`, and adds a fixture from the previous release to `tests/fixtures/state/`.
3. **Unknown state keys are ignored**, so a 0.2 build can open a 0.1 state without crashing (spec 05 §6).
4. **Presets stay plain XML** (`.brpreset`) and never embed audio (spec 05 §4).
5. **Shipped behaviour is preserved by default.** New features are off by default; with them off, output matches the golden renders.

## 2. Realtime safety rules (audio thread)

- No `new`, `malloc`, `std::vector` growth, `std::string` creation, `juce::String`, `juce::Logger`, `std::mutex`, file I/O or `setValueNotifyingHost` inside `processBlock` or `Engine::process`.
- Buffers for a feature are sized in `prepare()` and checked there against the maximum block size.
- Cross-thread values use `std::atomic` or the `SeqBox` pattern (spec 06 §18). `SeqBox` payloads are atomic words since 0.0.2.
- Every new audio-thread path has an allocation check: build `br_core_tests` with an allocation hook (global `operator new` counter, asserted zero inside `Engine::process` calls) in CI job `core-alloc-check`. Add this job in Phase 0 (plan §3, 0.4).

## 3. Test infrastructure

### 3.1 Golden renders
- `tests/golden/render_hashes.txt` holds hashes of 12 standard renders. Configurations and hashing are defined in `tests/golden_render.cpp`.
- Hashes are computed on the Linux CI runner with GCC. On other platforms the comparison allows max absolute difference `1e-5` per sample (floating-point differences between compilers and CPUs).
- Named golden checks used by the feature specs:
  - **G-01**: default configuration, sequential chunk reverse, 2 s of a 220 Hz tone plus a click train, seed 1.
  - **G-02**: reordered chunks with gates and stutter on, seed 77.
  - **G-03**: whole-file reverse with Echo on, seed 1977 (the "Random cut-up" factory preset seed).
- A PR that changes a golden hash must explain why in its description.

### 3.2 Fixtures
- Audio: `tests/fixtures/audio/` — click train, drum loop, sustained vowel. **Licence: generated by our own scripts (`tools/fixtures/generate.py`) or CC0.** Keep total size under 10 MB; use short clips.
- State: one XML per shipped version (`v0.0.2_default.xml`, `v0.0.2_complex.xml`), created from the 0.0.2 build and committed once.

### 3.4 Host testing matrix (spec 06 §17)
Use free or trial hosts so testing costs little:
- **Linux:** Carla (free, in apt) for VST3 and CLAP smoke tests; Reaper trial (Linux build) if available.
- **Windows:** Reaper (evaluation licence), Ableton Live trial, Bitwig trial, FL Studio trial.
- **macOS:** Logic Pro trial (AU), Reaper, Ableton Live trial.
- Each release records: host name and version, OS, the scenarios from spec 06 §17 that passed.

## 6. Decisions to record before work starts

- **[decision] macOS deployment target.** Proposal: 11.0 (Big Sur). Affects which Macs can run the product. Record in this file, dated.
- **[decision] Windows signing method.** OV certificate on CI, or Azure Trusted Signing. Record the choice and secrets names.
- **[decision] Time-stretch library.** Build our own (F-08 spike), or license a library. A GPL library is not compatible with the MIT source licence in `LICENSE` unless the project itself changes licence; record the outcome.
- **[decision] Universal binary policy.** Build both slices on every PR, or only on release branches. Proposal: every PR on Linux and macOS arm64; full universal on release branches and `main`.
- **[decision] Bus count.** F-06 proposes exactly two FX buses (A and B), matching spec 02 §10. Changing this later changes parameter IDs, so decide now.

## 8. Release checklist (every beta)

1. All CI jobs green on the release commit (Linux, macOS, Windows, sanitizers, allocation check).
2. Golden hashes unchanged or documented.
3. Signed artifacts verified (macOS notarization ticket stapled; Windows signature valid).
4. Host matrix results recorded (§3.4).
5. `auval` pass recorded; Logic Pro state round trip recorded.
6. Diagnostics log tested on each OS (F-05).
7. Release notes and spec 08 updated.
8. Publish as pre-release only until spec 06 §20 criteria are met.

## 10. Known gaps in the current codebase that the roadmap depends on

These were found while writing these specs. Each is small, and fixing them first reduces risk.

1. **Tests not run under sanitizers in CI.** Add the jobs in plan §3, 0.4.
2. **Allocation on the message-thread side is not checked.** Not a correctness risk, but it matters for the allocation check to be meaningful. No action beyond the audio-thread check.
3. **`Engine::process` is one long function (about 380 lines).** Splitting it into named stages (input, scheduling, rendering, pan/phase, gate, FX, output) before F-06 reduces the bus merge conflicts. Do it as a refactor PR with golden tests as the safety net.
4. **`BackReverseProcessor::processBlock` reads `getPlayHead()` every block.** Acceptable today; cache the `AudioPlayHead` pointer in `prepareToPlay` if the benchmark shows cost.
5. **State stores absolute paths only** (addressed by F-04).
6. **Standalone sample-rate changes trigger an asynchronous reload** (`prepareToPlay` → `callAsync` in `PluginProcessor.cpp`). Add a test with two sample rates to confirm the source is re-derived and the transport stops cleanly.
7. **The screenshot harness and its CMake lived only in the session scratch area.** Commit it under `tools/snapshot/` (plan §3, 0.5).
8. **Compiler warnings** listed in the 0.0.2 build log (`-Wshadow` in `UI.h`, `-Wmisleading-indentation`, `-Wfloat-equal`). Fix them in the editor split PR so the new code starts warning-free, and make `-Werror` for `src/core` a CI gate.
